🔍 Unit 4: Software Development Process — Pre-Unit Diagnostic

Assessment FOR Learning — Teacher Feedback
📋 Not Graded — Descriptive Feedback Only
Purpose: Check your readiness to start the software-development unit. Your teacher will use this to gauge your ability to plan, decompose, debug, and write tests — skills that build on Units 1-3.
Question 1 — Planning a small program
Suppose the task is: "compute and print a student's average from three test marks". Before writing any code, list the inputs, the steps, and the outputs (an IPO chart in three sections).
Question 2 — Pseudocode practice
Write pseudocode (NOT Python) that reads a list of marks from the user and prints the highest. End the list with the sentinel -1. Use SET, WHILE, IF, PRINT.
Question 3 — Identifying error types
Classify each as syntax error, runtime error, or logic error:
  1. if x > 5 (missing colon)
  2. print(scores[100]) for a list of 5 items
  3. A function that always returns one less than it should
  4. int("abc")
  5. An if/elif chain that incorrectly classifies all passing grades as Level 1
Question 4 — Test design
For a function is_even(n) that returns True when n is even, list four test cases (input and expected output) covering different categories.
Question 5 — Debugging strategy
A program is supposed to print numbers 1 through 5 but prints nothing. In one or two sentences, describe how you would diagnose what is wrong.
Question 6 — Files in everyday life
Give one practical reason a program might need to read or write a file (i.e., why we cannot just keep data in variables).
Question 7 — Documentation
Below is an undocumented function. Write a one-line docstring that explains what it does.
def f(x): return x * 5 / 9 - 32 * 5 / 9
Question 8 — Confidence
Rate 1-5:
  • Writing pseudocode before coding
  • Designing test cases
  • Reading error tracebacks
  • Using files (open/read/write)
  • Documenting my own code
