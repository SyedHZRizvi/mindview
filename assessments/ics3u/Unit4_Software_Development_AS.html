Question 1 — SDLC order
Which of these is the correct order of stages in the software-development process?
Solution:
Understand → Design → Code → Test → Document → Maintain. You cannot solve a problem you have not understood, and you cannot test before code exists.
Question 2 — IPO charts
In an IPO chart, what goes in the "Process" column?
Solution:
IPO = Input → Process → Output. The Process column lists the transformations turning Input into Output.
Question 3 — Error types
Match the error type to the description. Which one is a LOGIC error?
Solution:
Syntax errors prevent the program from starting; runtime errors crash it during execution; logic errors let it run but produce the wrong answer. (c) is the logic error.
Question 4 — Reading a traceback
A program crashes with:
Traceback (most recent call last): File "demo.py", line 7, in <module> print(scores[10]) IndexError: list index out of range
What does this tell you?
Solution:
The traceback names the file and line and the precise exception. Line 7 accessed an index past the end of the list.
Question 5 — Test categories
For a function average(nums) that averages a list of numbers, which input is the BEST boundary case to test?
Solution:
The empty list is the textbook boundary case for any function over a list. Most bugs hide here (division by zero, etc.).
Question 6 — File mode
Which mode does open("data.txt", "w") use, and what happens if data.txt already exists?
Solution:
"w" is write mode. The existing file is replaced (truncated to empty), then written. Use "a" for append.
Question 7 — with statement
Why is with open(...) as f: preferred over f = open(...); ...; f.close()?
Solution:
The with statement is a context manager that guarantees close() is called, even if an exception happens inside the block.
Question 8 — Assertion check
What does this do?
assert max(3, 7) == 7
Solution:
assert is a sanity check. If the expression is True, nothing happens; if False, it raises AssertionError. It is the simplest form of unit test.
Question 9 — Translating pseudocode
Which Python line corresponds to "SET count = count + 1"?
Solution:
count += 1 is the shorthand for count = count + 1. Option (a) computes a new value but doesn't store it.
Question 10 — Reading a file
After this code runs, what is in total?
# scores.txt contains: # 10 # 20 # 30 total = 0 with open("scores.txt") as f: for line in f: total += int(line.strip()) print(total)
Solution:
Each line read is "10\n", "20\n", "30\n". .strip() removes newlines, int(...) parses. Total: 10+20+30 = 60.
Question 11 — Docstring
Where does a docstring appear in a function definition?
Solution:
A docstring is the first statement inside a function body — a triple-quoted string immediately after the def ...: line, indented.
Question 12 — Rubber-duck debugging
What is "rubber-duck debugging"?
Solution:
The act of forcing yourself to verbalise each line often reveals what you had been glossing over. Surprisingly effective.
