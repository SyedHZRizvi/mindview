1. Course Overview & Vision

ICS3U introduces students to computer science. Students will design software independently and as part of a team, using industry-standard programming tools and applying the software-development life cycle. They will also write and use subprograms within computer programs. Students will develop creative solutions for a variety of problems, will document their work and communicate about it effectively, and will investigate ethical issues in computing and emerging technologies. They will also explore environmental impacts of computer use and study postsecondary opportunities in computer-related fields.

No formal prerequisite. ICS3U is the standard entry point into the secondary computer-science pathway. The course assumes solid Grade-10 mathematics (MPM2D recommended) and the ability to read carefully and follow detailed instructions, but no prior programming experience is required.

3. Big Ideas

  • Programs as precise instructions: A computer does exactly what you tell it. Programming is the discipline of writing instructions that are precise, complete, and correct.
  • Decomposition: Big problems become tractable when broken into small subproblems. Functions, modules, and procedures are the tools of decomposition.
  • Sequence, selection, iteration: Almost every program in any language is built from these three structured-programming control flows.
  • Software development is a process: Coding is one step in a cycle that also includes understanding the problem, designing, testing, debugging, and documenting.
  • Computer environments and systems: Programs do not run in a vacuum — they interact with operating systems, file systems, networks, and other software.
  • Computing in society: Software shapes daily life. Programmers carry ethical responsibility for the impact of what they build.

5. Strand A — Programming Concepts and Skills

A1. Demonstrate the ability to use different data types in computer programs.
A2. Use control structures (sequence, selection, iteration) to write code that performs a variety of tasks.
A3. Use simple subprograms (functions/procedures) to organise code into reusable units, and apply proper code-maintenance conventions (commenting, indentation, naming).

Specific Expectations (selected)

  • A1.1 Demonstrate the ability to declare, initialize, modify, and access primitive types (integer, real/float, character/string, Boolean) in computer programs.
  • A1.2 Use methods to manage data input and output in programs (e.g., format output to be displayed; validate input).
  • A1.3 Use one-dimensional arrays or lists to store and retrieve a collection of related values.
  • A2.1 Use the three structured-programming control structures — sequence, selection (if/elif/else), and iteration (while/for) — to write modular code.
  • A2.2 Apply Boolean expressions (comparison and logical operators) to control program flow, including short-circuit evaluation and the proper use of and, or, not.
  • A2.3 Use nested control structures (e.g., a loop inside a loop, or selection inside a loop) to solve problems of moderate complexity.
  • A3.1 Write functions that accept parameters and return values; explain the difference between formal parameters and arguments, and between local and global variables.
  • A3.2 Apply accepted style conventions to programs (meaningful identifiers, consistent indentation, internal comments, descriptive function docstrings).

6. Strand B — Software Development

B1. Apply a planned process for solving a problem in software development (problem definition → design → coding → testing → documentation).
B2. Use a variety of problem-solving strategies (decomposition, pattern recognition, trial-and-error, pseudocode, IPO charts, flowcharts) to design programs.
B3. Use systematic testing and debugging strategies to verify the correctness of programs and identify the cause and location of errors.

Specific Expectations (selected)

  • B1.1 Describe the stages of the software-development process (understanding the problem, planning the solution, coding, testing, documenting, maintaining).
  • B1.2 Read and write simple sequential files for data persistence.
  • B2.1 Use IPO (Input-Process-Output) charts and structured pseudocode to plan a solution before coding.
  • B2.2 Describe an algorithm using pseudocode or a flowchart; convert pseudocode into running code.
  • B3.1 Construct a test plan with normal, boundary, and invalid cases; record expected vs. actual behaviour.
  • B3.2 Use print-statement tracing or a debugger to locate the cause of a logic or runtime error.
  • B3.3 Distinguish syntax errors, runtime errors, and logic errors, and explain how each is diagnosed and fixed.
  • B3.4 Document programs with header comments, in-line comments, and a brief external description suitable for a peer or future maintainer.

7. Strand C — Computer Environments and Systems

C1. Demonstrate an understanding of components of computing environments (hardware components, peripherals, operating systems, application software).
C2. Demonstrate an understanding of how computers represent and process data (binary, character encodings, files) and how networks and the Internet operate at a high level.
C3. Use appropriate file-management and software-installation practices to set up and maintain a usable programming environment.

Specific Expectations (selected)

  • C1.1 Identify the major hardware components of a computer system (CPU, RAM, storage, input/output devices) and describe the role of each.
  • C1.2 Describe the function of an operating system (process management, file system, user interface, device drivers).
  • C2.1 Convert simple values between decimal, binary, and hexadecimal; explain how integers and characters are stored in memory.
  • C2.2 Describe how a computer connects to a network and to the Internet (NIC, router, IP address, DNS) at a non-technical level.
  • C2.3 Identify common file types (.py, .txt, .csv, .png, .pdf, .zip) and explain why file extensions matter.
  • C3.1 Install and configure a development environment (text editor or IDE, Python interpreter) on a personal computer.
  • C3.2 Use directory structures, relative and absolute paths, and basic file operations (move, copy, rename, delete) at the command line.

8. Strand D — Topics in Computer Science

D1. Describe key emerging areas of computer science (artificial intelligence, cloud computing, mobile computing, cybersecurity, the Internet of Things).
D2. Analyse ethical, social, and environmental issues related to the use of computers (privacy, intellectual property, accessibility, e-waste, energy footprint).
D3. Describe postsecondary education and career opportunities related to computer studies, including in Ontario and Canada.
D4. Describe key contributions to the history and development of computer science.

Specific Expectations (selected)

  • D1.1 Describe at a non-technical level what is meant by artificial intelligence, machine learning, and large-language models, and give one everyday example of each.
  • D1.2 Describe what is meant by cybersecurity, and identify common attack types (phishing, malware, weak passwords) and basic defences (strong passwords, multi-factor authentication, software updates).
  • D2.1 Identify common threats to personal privacy online (data collection, tracking, surveillance) and describe practical mitigations.
  • D2.2 Distinguish open-source, free, and proprietary software licensing models, and the ethical responsibilities of programmers.
  • D2.3 Describe the environmental impact of computing (energy use, e-waste, mining for materials) and the role of recycling programs.
  • D3.1 Identify at least three university programs and three college programs in Ontario related to computer science, and three career roles a graduate may pursue.
  • D4.1 Identify at least three landmark contributions to computing (e.g., Babbage, Lovelace, Turing, Hopper) and one Canadian contributor.

9. Programming Languages & Environments

The Ontario curriculum is language-agnostic. The most common choices in Ontario boards are Python and Java. This MindView build defaults to Python because its syntax is closest to pseudocode, lowering cognitive load for first-time programmers, with Java parallel examples added where appropriate.

LanguageStrengthsTrade-offs
Python 3.x (default)Readable syntax close to pseudocode; no boilerplate; instant feedback in REPL; large standard library.Dynamic typing means some bugs only surface at run time. Slower than compiled languages for heavy computation.
JavaStatic typing makes types explicit; aligns with most university CS1 courses; widely used in industry.More verbose at the start (every program needs a class and a main method).

Recommended Tooling

  • Editor/IDE: Thonny (free, beginner-friendly Python IDE), VS Code (free, cross-platform), IDLE (ships with Python).
  • Online options: repl.it, Trinket, Google Colab — no install required, work in any browser.
  • Testing: Built-in Python REPL for quick checks; unittest module for structured tests (more in ICS4U).

10. STSE Connections & Career Pathways

Sample STSE Topics (Strand D)

  • Online privacy and digital footprints — how social-media posts persist.
  • Password security and multi-factor authentication.
  • Algorithmic bias in everyday systems (recommendation feeds, search ranking).
  • Environmental impact of data centres and cryptocurrency mining.
  • Open-source software (Linux, Python, Wikipedia) and contribution culture.
  • The digital divide — equitable access to computing in schools and remote communities.

Career Pathways

Software developer, web/mobile developer, data analyst, cybersecurity technician, game designer, IT support technician, network technician, UX/UI designer, computing teacher. Many computer-studies graduates also enter adjacent fields including business analytics, engineering, journalism, and the digital arts.

Sample Ontario Postsecondary Pathways

  • Universities (BSc / BEng): Computer Science, Software Engineering, Computer Engineering — e.g., U of Waterloo, U of Toronto, McMaster, Western, Queen's, Carleton, York, Ottawa, Guelph.
  • Colleges (diploma / advanced diploma): Computer Programmer / Programmer-Analyst, Game Development, Cybersecurity, Mobile Development — e.g., Seneca, Centennial, Sheridan, Algonquin, Conestoga, George Brown.

12. Evaluation Policy (Growing Success, 2010)

ComponentWeightDescription
Term Work70%Unit tests, programming assignments, quizzes, lab worksheets, code reviews — balanced across the four achievement categories.
Final Evaluation30%Cumulative final exam (~20%) and a final culminating programming project (~10%). Together capped at 30%.

Assessment Types

  • ASAssessment AS Learning: self-directed practice quizzes — student uses results to plan study; not graded.
  • FORAssessment FOR Learning: teacher diagnostics — descriptive feedback only, not graded.
  • OFAssessment OF Learning: summative unit tests, programming assignments, culminating project, and final exam — counted toward final grade.
Levels of Achievement: Level 4 (80–100%, thorough and insightful), Level 3 (70–79%, considerable effectiveness — provincial standard), Level 2 (60–69%), Level 1 (50–59%), R (below 50%, insufficient).

Learning Skills & Work Habits (reported separately)

Responsibility, Organization, Independent Work, Collaboration, Initiative, Self-Regulation — each rated E (Excellent) / G (Good) / S (Satisfactory) / N (Needs Improvement).
