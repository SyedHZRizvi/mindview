2.1 — Comparison Operators and Boolean Expressions
The six comparison operators (==, !=, <, <=, >, >=); how a comparison produces a bool; chained comparisons
# Every comparison evaluates to True or False print(5 > 3) # True print(10 == 10.0) # True — int and float compare by value print("abc" < "abd") # True — lexicographic order print(1 < 5 < 10) # True — Python allows chained comparisons print(5 != 6) # True
📖 Lesson Notes — Ontario Curriculum

A Boolean expression is any expression that evaluates to one of the two values True or False. Comparison operators are the most direct way to produce a Boolean. Python has six: == (equal), != (not equal), < (less than), <= (less than or equal), > (greater than), and >= (greater than or equal). These look very similar to ordinary mathematics, with one critical difference: = alone is assignment, not comparison. A common beginner mistake is writing if x = 5 when they meant if x == 5; Python flags this as a syntax error (some other languages, like C, silently turn it into a hidden bug).

Comparisons work on any types where comparison makes sense. Numbers compare by value: 5 == 5.0 is True even though one is an int and the other a float. Strings compare in lexicographic order, which is dictionary order based on Unicode code points: "apple" < "banana" is True, and "Z" < "a" is True because uppercase letters come before lowercase ones in Unicode. Comparing across unrelated types (a number and a string, for instance) raises a TypeError in Python 3.

Python supports a feature that many other languages do not: chained comparisons. 1 < x < 10 means "x is between 1 and 10 exclusively". This reads like mathematics and is equivalent to 1 < x and x < 10, but the chained form is more concise and Python evaluates x only once. In Java or C, you must write the explicit and form. Chained comparisons compose: a < b < c < d works as expected.

  • Boolean expression — any expression that yields True or False.
  • Comparison operator — one of ==, !=, <, <=, >, >=.
  • Equality (==) — tests whether two values are equal.
  • Inequality (!=) — tests whether two values are unequal.
  • Lexicographic order — dictionary-style comparison based on character codes.
  • Chained comparison — combining multiple comparisons in one expression (Python-specific).

Worked example — evaluating Boolean expressions

x = 7
y = 3

print(x == y)        # False
print(x != y)        # True
print(x >= y * 2)    # True  — 7 >= 6
print(0 < x < 10)    # True  — chained
print("hi" == "Hi")  # False — case-sensitive

Each expression evaluates in O(1) time. Comparing strings is technically O(n) in the length of the shorter string, but the strings here are short. Notice that "hi" == "Hi" is False: string comparison is case-sensitive. If you want case-insensitive comparison, lowercase both sides first: a.lower() == b.lower().

  • Using = instead of == in a condition — syntax error in Python, logic bug in C/Java.
  • Comparing floats with == after arithmetic — rounding can make 0.1 + 0.2 == 0.3 evaluate to False. Use a tolerance.
  • Comparing different types: "5" < 6 raises TypeError in Python 3.
  • Forgetting case-sensitivity of string comparison.
  • Confusing != with =! (the second is not a valid operator).

Curriculum expectation: Strand A, Expectation A2.2 — "apply Boolean expressions (comparison and logical operators) to control program flow".

2.2 — Logical Operators: and, or, not
Combining Boolean expressions; truth tables; short-circuit evaluation; De Morgan's laws
# Combining Boolean expressions with and / or / not age = 17 has_id = True can_vote = age >= 18 and has_id teen = 13 <= age <= 19 non_teen = not teen need_help = age < 8 or age >= 80 print(can_vote, teen, non_teen, need_help) # False True False False
📖 Lesson Notes — Ontario Curriculum

Logical operators let you combine Boolean expressions to express more complex conditions. Python uses the keywords and, or, and not — in Java they are written as &&, ||, and !. The behaviour is captured by a truth table: A and B is True only when both A and B are True; A or B is True when at least one is True; not A flips the value. These are the building blocks of every conditional in every program.

Python uses short-circuit evaluation: in A and B, if A is false, B is never evaluated; in A or B, if A is true, B is never evaluated. This is not just an optimisation; it lets you write guards like if y != 0 and x / y > 5 without crashing on division by zero when y is zero. Short-circuit evaluation also means the order of operands matters in subtle ways — put the cheap, deciding test first.

De Morgan's laws are essential for simplifying negated compound conditions. They state: not (A and B) is equivalent to (not A) or (not B); and not (A or B) is equivalent to (not A) and (not B). So "not (full and clean)" becomes "empty or dirty". Applying De Morgan's laws by hand is a frequent topic on Grade-11 tests and a real skill in reading complex Boolean code.

  • Logical operator — and, or, not — combine Booleans.
  • Truth table — a table listing the result for every combination of operand values.
  • Short-circuit evaluation — the second operand of and/or is skipped when the first determines the result.
  • De Morgan's laws — rules for distributing not across and/or.
  • Operator precedence — not binds tightest, then and, then or.
  • Truthy / falsy — non-Boolean values used in a Boolean context (e.g., 0, "", None, [] are falsy; almost everything else is truthy).

Worked example — truth table for an admission-rules expression

# "You may enter if you are at least 18, OR if you are at least 16 with a guardian."
def can_enter(age, has_guardian):
    return age >= 18 or (age >= 16 and has_guardian)

print(can_enter(20, False))   # True  — 20 >= 18
print(can_enter(16, True))    # True  — 16+ with guardian
print(can_enter(16, False))   # False
print(can_enter(15, True))    # False — too young even with guardian

The parentheses around age >= 16 and has_guardian are not strictly required because and binds tighter than or, but they make the intent obvious. Each call runs in O(1). Studying the four results above gives a small truth table that documents the rule.

Worked example — applying De Morgan's laws

raining = True
windy   = False

# Original
print(not (raining and windy))    # True

# After De Morgan's
print((not raining) or (not windy))  # True — same answer

The two expressions are logically equivalent for all inputs. Knowing this lets you simplify conditions: not (x > 5 and y > 5) can be rewritten as x <= 5 or y <= 5, which some readers find clearer.

  • Writing x == 1 or 2 or 3 meaning "x is 1, 2, or 3" — this is a serious bug. 2 on its own is truthy, so the whole expression is always True. Write x == 1 or x == 2 or x == 3, or better x in (1, 2, 3).
  • Forgetting precedence: a or b and c is a or (b and c), not (a or b) and c. Use parentheses if unsure.
  • Using & or | (bitwise operators) instead of and/or — they sometimes give the same answer on plain Booleans but behave differently on numbers.
  • Negating a complex condition without applying De Morgan's laws — easy to invert the wrong operator.

Curriculum expectation: Strand A, Expectation A2.2 — "apply Boolean expressions (comparison and logical operators) to control program flow, including short-circuit evaluation".

2.3 — Selection: if, elif, else
One-branch if; two-branch if/else; multi-branch if/elif/else; indentation as syntax
# Letter-grade classifier (Ontario Achievement Chart) def letter_grade(percent): if percent >= 80: return "Level 4" elif percent >= 70: return "Level 3" elif percent >= 60: return "Level 2" elif percent >= 50: return "Level 1" else: return "R" print(letter_grade(85)) # Level 4 print(letter_grade(55)) # Level 1
📖 Lesson Notes — Ontario Curriculum

Selection — choosing which branch of code to run — is one of the three pillars of structured programming alongside sequence and iteration. The simplest form is a one-branch if: "do this only if the condition is true". The else clause adds a fallback branch: "otherwise do this". The elif clause (short for "else if") chains additional conditions; an if/elif/else chain is mutually exclusive, meaning at most one branch executes, and they are checked top to bottom. Once a condition is true, the corresponding branch runs and the rest are skipped.

The order of conditions matters. In a letter-grade chain, you must check >= 80 before >= 70: every grade of 85 also satisfies >= 70, so if that branch came first every passing student would be classified as Level 3. Write the most restrictive condition first, or use disjoint conditions like 70 <= percent < 80. Tracing through example inputs by hand is the easiest way to verify your chain is right.

In Python, the body of each branch is identified by indentation. Indenting a line by 4 spaces marks it as inside the if; outdenting marks the next statement as outside. This is not just convention — it is part of the language syntax. Java, C, and JavaScript use curly braces { } for the same purpose. Either way, the principle is the same: a control structure has a body, and the body is grouped together.

  • Selection — choosing among alternative code paths based on a condition.
  • If statement — runs its body when the condition is true.
  • Else clause — runs when the if condition is false.
  • Elif clause — chains another condition after a failed if.
  • Mutually exclusive — only one branch of the chain runs.
  • Block — the indented body of a control structure.
  • Nested if — an if inside another if's body.

Worked example — classifying triangles

def triangle_type(a, b, c):
    if a == b == c:
        return "equilateral"
    elif a == b or b == c or a == c:
        return "isosceles"
    else:
        return "scalene"

print(triangle_type(5, 5, 5))   # equilateral
print(triangle_type(3, 4, 4))   # isosceles
print(triangle_type(3, 4, 5))   # scalene

The chained comparison a == b == c is true only when all three are equal. The order of the chain is important: equilateral must come before isosceles, because every equilateral triangle is also (technically) isosceles. The function is O(1) regardless of the side lengths.

Worked example — input validation

age_str = input("Enter age: ")

if not age_str.isdigit():
    print("Error: age must be a non-negative whole number.")
elif int(age_str) > 130:
    print("Error: that age is implausible.")
else:
    age = int(age_str)
    print(f"You are {age} years old.")

The elif branch only runs when the first check passed, so we know int(age_str) will not crash. This is a good template for any program that takes user input: validate before computing.

  • Using elif when the conditions are not mutually exclusive — results in silently-skipped branches.
  • Putting the most general condition first (if percent >= 50 before if percent >= 80) — classic order bug.
  • Forgetting the colon at the end of if/elif/else — SyntaxError.
  • Mixing tabs and spaces — IndentationError or, worse, code that runs but does the wrong thing.
  • Writing if x == 1 or 2: when you mean if x == 1 or x == 2: (the former is always true).

Curriculum expectation: Strand A, Expectation A2.1 — "use the three structured-programming control structures — sequence, selection, and iteration — to write modular code".

2.4 — Iteration: while and for Loops
When to use each loop; range(); the accumulator pattern; sentinel-controlled loops; the break statement
# Two ways to sum the numbers 1..100 # Using a for loop with range total = 0 for i in range(1, 101): total += i print(total) # 5050 (Gauss's sum) # Using a while loop with an explicit counter total, i = 0, 1 while i <= 100: total += i i += 1 print(total) # 5050
📖 Lesson Notes — Ontario Curriculum

Iteration — repeating a block of code — is what makes a computer dramatically more powerful than a calculator. Python has two main loop constructs: for and while. A for loop iterates over a known sequence: a list, a string, a file, or a range(start, stop, step). The loop variable takes on each value in turn. A while loop continues as long as a Boolean condition remains true, and is used when you don't know in advance how many iterations are needed (reading user input until they type "quit", waiting for a network response, etc.).

The accumulator pattern is the most common loop idiom: initialise a result variable outside the loop, update it inside the loop, and use it after the loop. The accumulator may be a number (sum, product, count, max-so-far), a Boolean (any/all), a string, or a list. Recognising this pattern lets you translate plain-English questions ("how many students passed?") into code almost mechanically.

A sentinel-controlled loop is a while idiom where a special "stop" value (such as "quit", -1, or empty string) ends the loop. The sentinel must be something that could not appear as legitimate data. The break statement exits the nearest enclosing loop immediately; it is useful for early exit when a search succeeds. Avoid break in deeply nested code — it can make the flow hard to follow.

  • Loop — a control structure that repeats its body.
  • Loop body — the indented block that repeats.
  • Loop variable — the variable that changes each iteration.
  • Counter-controlled loop — a loop that runs a known number of times (for i in range(...)).
  • Conditional loop — a loop controlled by a Boolean test (while).
  • Accumulator pattern — a variable that builds up a result across iterations.
  • Sentinel — a special value that signals the end of input.
  • Off-by-one error — looping one too few or one too many times (range(n) vs range(n+1)).

Worked example — finding the largest number entered

# Sentinel-controlled while loop using -1 to stop.
largest = None

while True:
    s = input("Enter a positive number (-1 to finish): ")
    n = int(s)
    if n == -1:
        break
    if largest is None or n > largest:
        largest = n

if largest is None:
    print("No numbers entered.")
else:
    print(f"The largest was {largest}.")

The while True with a break is a common idiom for "loop until told to stop". The accumulator (largest) starts at None rather than 0 because we need to handle the case where no numbers are entered. Each iteration does O(1) work; the total runtime is O(n) where n is the number of values entered.

Worked example — counting vowels in a string

def count_vowels(text):
    vowels = "aeiouAEIOU"
    count = 0                       # accumulator initialised outside
    for ch in text:                 # loop over each character
        if ch in vowels:
            count += 1
    return count

print(count_vowels("Programming Foundations"))  # 8

The for ch in text idiom iterates over the characters of the string in order. The in operator on a string tests substring membership, but on a single character against the vowels string it tests whether that character is one of the vowels. Total runtime is O(n) in the length of the text.

  • Off-by-one: range(1, n) goes 1 to n-1, not 1 to n. Use range(1, n+1) to include n.
  • Infinite loops: a while whose condition never becomes false. Always make sure the loop variable changes inside the body.
  • Initialising an accumulator inside the loop instead of outside — it resets every iteration.
  • Forgetting that for x in 10: does not work — you must iterate over a sequence; use range(10).
  • Modifying a list while iterating over it — can skip or repeat elements.

Curriculum expectation: Strand A, Expectation A2.1 — "use the three structured-programming control structures — sequence, selection, and iteration — to write modular code".

2.5 — Nested Control Structures
Loops inside loops, selections inside loops, selections inside selections; nested-loop tracing; complexity intuition
# Print a multiplication table 1..5 for i in range(1, 6): for j in range(1, 6): print(f"{i*j:4d}", end="") print() # newline after each row
📖 Lesson Notes — Ontario Curriculum

Once you understand selection and iteration on their own, you can combine them. A nested loop is a loop whose body contains another loop. A nested if is an if whose body contains another if. These compositions let you process two-dimensional data, validate complex conditions, and express algorithms that would not fit in a single linear loop. They also tend to be where bugs hide: each level of nesting adds another dimension that must be reasoned about.

The execution flow of nested loops is mechanical: the outer loop runs once, then the inner loop runs to completion, then the outer loop advances and the inner loop runs to completion again, and so on. If the outer loop runs m times and the inner loop runs n times each pass, the inner body executes a total of m × n times. This multiplication gives a first intuition for algorithm complexity: a doubly nested loop over a list of length n does about n2 work (we will call this O(n2) in ICS4U). For n = 1000 that is a million operations — still fast on a modern computer, but for n = 1 000 000 it would be a trillion, far too slow.

The most reliable way to verify nested code is tracing — making a small table that records the value of every variable at every iteration. Tracing exposes off-by-one errors, accumulators that reset too often, and conditions that always fire or never fire. The table is a small investment that saves hours of head-scratching later.

  • Nested loop — a loop inside another loop.
  • Nested if — an if inside another if's body.
  • Outer loop / inner loop — the enclosing and enclosed loops respectively.
  • Trace table — a pencil-and-paper table tracking variable values through execution.
  • Loop invariant — a property that holds at the start of every iteration.
  • Polynomial growth — n, n2, n3 work; the exponent equals the number of nested loops over the data.

Worked example — counting pairs that sum to a target

def pair_count(nums, target):
    count = 0
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):  # j > i avoids duplicates
            if nums[i] + nums[j] == target:
                count += 1
    return count

print(pair_count([1, 9, 4, 6, 5, 5], 10))   # 3
# pairs that sum to 10: (1,9), (4,6), (5,5)

The outer loop runs n times; the inner loop runs n − i − 1 times for outer iteration i. Total comparisons is roughly n(n−1)/2, which grows as n2. For a list of 6 numbers we do 15 comparisons; for 60 numbers we do 1770. This O(n2) cost is the canonical price of "compare everything to everything".

Worked example — tracing a small nested loop

for i in range(3):
    for j in range(3):
        if i == j:
            print("*", end=" ")
        else:
            print(".", end=" ")
    print()

# Output:
# * . .
# . * .
# . . *

The diagonal of a 3×3 grid. The inner print(..., end=" ") stays on the same line; the outer print() ends each row with a newline. Total iterations: 3 × 3 = 9 cells.

  • Reusing the same loop variable name for both outer and inner loops — the inner overwrites the outer.
  • Forgetting that break only exits the nearest loop, not all enclosing loops.
  • Mis-indentation that puts the inner loop's body outside the outer loop — usually causes a logic error, not a syntax error.
  • Resetting an accumulator inside the inner loop when it should reset between outer iterations — or vice versa.
  • Trying to write a triply nested loop over the same data — almost always there is a smarter algorithm.
