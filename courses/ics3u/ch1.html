1.1 — Your First Python Program
What a program is; running Python; the print() function; using the REPL; saving a .py file
# hello.py — the traditional first program print("Hello, ICS3U!") print("My name is Ada and I am a Grade 11 student.") print("This program prints three lines.")
📖 Lesson Notes — Ontario Curriculum

A computer program is a sequence of instructions written in a programming language that a computer can execute. The computer follows the instructions exactly — it has no common sense, no patience, and no creativity. The skill of programming is the skill of expressing what you want with enough precision that the computer can do it. Python is a popular first language because its syntax is close to plain English: you write print("Hello") and Python prints "Hello". Compare this with the equivalent in Java, which requires you to declare a class and a main method before you can do anything.

Python programs can be run in two ways. The REPL (Read-Eval-Print Loop, the interactive prompt you get by typing python in a terminal or by opening Thonny/IDLE) lets you type one line at a time and see the result immediately — it is excellent for experimentation. The other way is to save instructions in a script file with the .py extension and run it as a whole: python hello.py. Scripts are how real programs are stored and shared.

The print() function is the simplest way to produce output. By default it writes its arguments to standard output (the terminal) followed by a newline. Multiple values separated by commas appear with spaces between them: print("Score:", 95) outputs Score: 95. We will see f-strings later for more sophisticated formatting.

  • Program — a precise sequence of instructions in a programming language.
  • Source code — the human-readable text of a program.
  • Interpreter — software that reads source code and executes it directly. Python uses an interpreter.
  • Compiler — software that translates source code into machine code first, then runs the result. Java and C use compilers.
  • REPL — interactive Read-Eval-Print Loop; instant feedback.
  • Script — a saved program in a file (Python uses .py).
  • Standard output (stdout) — the default destination for printing, normally the terminal.
  • Function call — using a function by writing its name followed by parentheses, e.g. print(...).

Worked example — a complete first program

# greeting.py
# Author: A. Lovelace    Date: 2026-05-31
# Purpose: greet the user with three lines of output.

print("=" * 30)
print("Welcome to ICS3U")
print("Today's topic: Intro to Python")
print("=" * 30)

Lines beginning with # are comments — they are ignored by the interpreter and exist for human readers. The expression "=" * 30 uses string multiplication to build a 30-character separator. The program prints four lines in order. There is no input and no calculation; the program demonstrates only sequence (instructions running top to bottom).

  • Forgetting the parentheses: writing print "hello" works in Python 2 but is a SyntaxError in Python 3. We always use Python 3.
  • Forgetting the closing quote on a string — gives a SyntaxError.
  • Naming a file print.py or random.py — can shadow Python's built-in modules and cause confusing import errors.
  • Mixing tabs and spaces for indentation — even though this first program has no indentation, doing so later is a common cause of IndentationError.

Curriculum expectation: Strand A, Expectation A1.2 — "use methods to manage data input and output in programs (e.g., format output to be displayed; validate input)".

1.2 — Variables and Data Types
Assignment statements; primitive types (int, float, str, bool); type(); type conversion with int(), float(), str()
# Four primitive types and a type check name = "Hopper" # str — text age = 16 # int — whole number average = 85.4 # float — number with decimal is_enrolled = True # bool — True or False print(type(name)) # <class 'str'> print(type(age)) # <class 'int'> print(type(average)) # <class 'float'> print(type(is_enrolled)) # <class 'bool'>
📖 Lesson Notes — Ontario Curriculum

A variable is a named storage location for a value. In Python, you create one by writing an assignment statement: age = 16. The left side is the name; the right side is the value; the = sign means "store the value into the name". Reading the variable afterwards retrieves the value: print(age) outputs 16. Choose variable names that describe what the value means — final_grade is far better than x, even though both work mechanically.

Every value has a data type that determines what operations are legal on it. The four primitive types in Python are int (whole numbers like 17), float (numbers with a decimal point like 3.14), str (text inside quotes like "Ada"), and bool (the two literals True and False). You can ask Python the type of any value with type(value). Python is dynamically typed: a variable can be re-bound to a value of a different type, e.g. x = 5 then x = "hello". Java is statically typed and would forbid this.

Sometimes you need to convert one type to another. This is called type conversion or casting. int("42") converts the string "42" to the integer 42. str(95) converts the integer back to "95". float("3.14") converts a string to a float. Conversion can fail: int("hello") raises a ValueError because there is no integer interpretation of those letters.

  • Variable — a name bound to a value.
  • Assignment — the statement name = value.
  • Identifier — the textual name of a variable, function, or class.
  • Primitive type — int, float, str, bool.
  • Literal — a value written directly in source code (17, "Ada", 3.14, True).
  • Type conversion / casting — converting a value from one type to another (e.g., int("12")).
  • Dynamic typing — the type of what a name refers to can change over time.

Worked example — storing and using a student record

name = "Hopper"
age = 16
gpa = 3.85

# Build a one-line description by converting numbers to strings.
description = name + ", age " + str(age) + ", GPA " + str(gpa)
print(description)
# Output: Hopper, age 16, GPA 3.85

The + operator on strings means concatenation: joining end to end. You cannot concatenate a string with a number directly — that would be a TypeError. The explicit str() conversions make the intent obvious. Each step here is O(1) (constant time), so the runtime does not depend on the length of any input.

  • Forgetting that = is assignment and == is comparison.
  • Trying to add a number and a string without converting one: "Age: " + 16 raises TypeError.
  • Re-using a name like list or str as a variable, shadowing the built-in type.
  • Identifier rules: must start with a letter or underscore; case-sensitive (Score and score are different).
  • Assuming integer division: 5 / 2 in Python 3 is 2.5 (a float), not 2.

Curriculum expectation: Strand A, Expectation A1.1 — "demonstrate the ability to declare, initialize, modify, and access primitive types (integer, real/float, character/string, Boolean) in computer programs".

1.3 — Arithmetic and Expressions
Arithmetic operators (+ - * / // % **); operator precedence; parentheses; floating-point quirks
# Standard arithmetic in Python print(7 + 3) # 10 print(7 - 3) # 4 print(7 * 3) # 21 print(7 / 3) # 2.3333333333333335 (float division) print(7 // 3) # 2 (integer / floor division) print(7 % 3) # 1 (remainder / modulo) print(2 ** 10) # 1024 (exponentiation)
📖 Lesson Notes — Ontario Curriculum

Python provides the usual arithmetic operators plus a few that are less common in elementary mathematics. +, -, and * mean exactly what you would expect. Division splits into two: / always produces a float (true division), even when the result has no remainder (10 / 2 is 5.0, not 5). // is floor division, the integer part of the division with the fractional part discarded. % is the modulo (or remainder) operator: 17 % 5 is 2 because 17 divided by 5 leaves a remainder of 2. ** is the exponent operator: 2 ** 10 is 1024.

Operator precedence determines the order in which sub-expressions are evaluated. Python follows the standard mathematical order with one addition: exponentiation. From highest to lowest: **, then unary - (negation), then *, /, //, %, then +, -. Same-precedence operators normally evaluate left to right (exponentiation is the exception — it groups right-to-left, so 2 ** 3 ** 2 is 2 ** 9 = 512, not (2 ** 3) ** 2 = 64). When in doubt, use parentheses: they cost nothing and remove ambiguity.

Floating-point arithmetic is approximate, not exact. 0.1 + 0.2 in Python prints 0.30000000000000004, not 0.3, because base-2 floating point cannot represent decimal fractions exactly. This is not a Python bug; it is the IEEE-754 standard used by essentially every modern processor. When precise decimal arithmetic matters (money!), round the answer with round(value, 2) or use the decimal module.

  • Operator — a symbol like + that performs an operation.
  • Operand — the value an operator acts on.
  • Expression — any combination of values, names, and operators that yields a value.
  • Operator precedence — rules that determine the order of evaluation.
  • Floor division (//) — division rounded down to an integer.
  • Modulo (%) — the remainder after integer division.
  • Floating-point error — rounding caused by binary representation of decimals.

Worked example — an HST-tax calculator

# Compute total cost including 13% Ontario HST.
price = 24.99
tax_rate = 0.13

tax = price * tax_rate
total = price + tax

# round to 2 decimal places for currency display
print(round(total, 2))   # 28.24

The arithmetic runs in O(1). Note how round(value, 2) hides the floating-point noise: without it the answer might display as something like 28.2387. In financial software, real money values are typically stored as integer cents (or a fixed-point Decimal type) to avoid these issues entirely.

Worked example — tracing operator precedence

print(2 + 3 * 4)        # 14, because * binds tighter than +
print((2 + 3) * 4)      # 20, parentheses force + first
print(2 ** 3 ** 2)      # 512, exponent is right-associative: 2 ** 9
print(10 - 3 - 2)       # 5, subtraction is left-associative: (10-3)-2
print(7 // 2 + 1)       # 4: 7 // 2 = 3, then 3 + 1 = 4

If you have to think hard about the order, add parentheses. A few extra characters make the program much easier for the next reader (often yourself, a month later).

  • Confusing / (true division, float) with // (floor division, int).
  • Using ^ for exponentiation: in Python ^ is bitwise XOR, not power. Use **.
  • Comparing floats with == — nearly always wrong because of rounding. Use a tolerance: abs(a - b) < 0.0001.
  • Writing 2x instead of 2 * x — Python doesn't have implicit multiplication.
  • Forgetting that % is the modulo operator, not "percent".

1.4 — Input, Output, and Strings
input() returns a string; parsing numeric input; f-strings; escape sequences; basic string methods
# Interactive tip calculator bill = float(input("Bill amount ($): ")) people = int(input("Number of people: ")) tip = bill * 0.15 total = bill + tip per_person = total / people print(f"Tip: ${tip:.2f}") print(f"Total: ${total:.2f}") print(f"Per person: ${per_person:.2f}")
📖 Lesson Notes — Ontario Curriculum

An interactive program reads input from the user, processes it, and produces output. The simplest input function in Python is input(prompt): it displays the prompt, waits for the user to type a line and press Enter, then returns whatever they typed as a string. Even if the user types 42, the program receives the four-character string "42", not the integer 42. To do arithmetic you must convert with int() or float(). Forgetting this is the single most common bug in introductory programs.

Output formatting matters because raw values rarely look the way humans want to read them. A bill of 23.4 should display as $23.40 with two decimal places. Python's f-strings (formatted string literals) embed expressions directly inside a string: f"Total: ${total:.2f}" means "insert the value of total formatted as a fixed-point float with 2 decimal places". The f prefix is mandatory — without it, the braces are literal characters.

Escape sequences let strings contain special characters: \n is a newline, \t is a tab, \\ is a literal backslash, and \" is a literal double quote inside a double-quoted string. Strings also have many useful methods: .upper(), .lower(), .strip() (remove whitespace at ends), .replace(old, new), .split(sep) (break into a list of substrings).

  • Standard input (stdin) — default source of input, normally the keyboard.
  • Prompt — the message displayed to the user before they type.
  • Parsing — converting input text into a more useful type.
  • F-string — an expression-embedded literal of the form f"…{expr:spec}…".
  • Format specifier — the part after the colon (.2f, >10) that controls formatting.
  • Escape sequence — a two-character code beginning with \ that represents a special character.
  • String method — a function attached to a string value, called with dot syntax (s.upper()).

Worked example — a name-and-age form

first = input("First name: ").strip()
last  = input("Last name: ").strip()
year  = int(input("Birth year: "))

age = 2026 - year
full = f"{first} {last}"

print(f"Welcome, {full}!")
print(f"You are about {age} years old.")

The .strip() calls remove any stray spaces the user typed before or after their name. The int(input(...)) idiom parses the year on the spot — if the user types non-numeric input it raises ValueError (we will handle that gracefully later). The f-string lets us interleave variables and literal text without messy concatenation.

  • Forgetting to wrap input() with int() or float() — arithmetic on strings raises TypeError.
  • Calling int("3.5") — raises ValueError. Use float() first if a decimal is possible.
  • Missing the f prefix: "{x}" is the literal text {x}, not the value.
  • Confusing print("a", "b") (auto-inserts a space) with concatenation.
  • Reading from input but never storing the result — input() with no assignment discards what was typed.

Curriculum expectation: Strand A, Expectation A1.2 — "use methods to manage data input and output in programs (e.g., format output to be displayed; validate input)".

1.5 — Comments and Code Style
Why we comment; single-line and multi-line comments; meaningful variable names; PEP 8 basics (indentation, line length, snake_case)
# BAD STYLE — works but is hard to read a=5 b=9 c=a*b+1 print(c) # GOOD STYLE — same calculation, much clearer intent WIDTH = 5 HEIGHT = 9 TILES_NEEDED = WIDTH * HEIGHT + 1 # +1 spare tile print(f"Buy {TILES_NEEDED} tiles.")
📖 Lesson Notes — Ontario Curriculum

Code is read far more often than it is written. A program is finished only when it works and can be understood. Two tools make code readable: comments and good names. A comment is a note for human readers, ignored by the interpreter. Python uses # for a single-line comment; for longer notes most programmers write several # lines, although a triple-quoted string at the top of a file or function is also conventional. Comments should explain why, not what: the code already shows what it does, but the reader needs to know why a particular threshold was chosen, why a tricky case is handled the way it is, or what assumptions the function depends on.

Meaningful variable names are even more important than comments. students_passing tells a future reader what the value represents; x does not. Python's style guide, called PEP 8, recommends snake_case for variables and functions (final_grade, compute_average), UPPER_CASE for constants (MAX_STUDENTS = 30), and PascalCase for class names (introduced later). PEP 8 also recommends 4-space indentation, lines no longer than 79 (or 100) characters, and one statement per line.

Beyond names and comments, two basics make a huge difference. Consistent indentation is not optional in Python — it is part of the syntax. Use exactly 4 spaces (or configure your editor to expand tabs to spaces) and never mix tabs and spaces in the same file. Whitespace around operators (a = 5 not a=5, x + y not x+y) is recommended by PEP 8 and dramatically improves scannability.

  • Comment — a note for human readers, ignored by the interpreter; begins with # in Python.
  • PEP 8 — the official Python style guide.
  • Identifier — the name of a variable, function, or class.
  • snake_case — lowercase words separated by underscores; convention for Python variables and functions.
  • Magic number — a literal value in code with no name or explanation. Use a named constant instead.
  • Header comment — comment at the top of a file giving author, date, and purpose.
  • Docstring — a triple-quoted string at the start of a function or module describing its purpose.

Worked example — refactoring for style

# BEFORE — works, but unreadable
def f(a,b,c):
 t=a*0.13
 g=a+t
 return g/c

# AFTER — same logic, professional style
def split_bill(subtotal: float, tax_rate: float, people: int) -> float:
    """Return each person's share of a tax-inclusive bill."""
    tax   = subtotal * tax_rate
    total = subtotal + tax
    return total / people

# Usage:
print(round(split_bill(60.00, 0.13, 4), 2))   # 16.95

The refactored version uses descriptive names, four-space indentation, a docstring explaining the purpose, and type hints (a Python 3 feature that makes types visible without changing behaviour). Both versions compute the same value in O(1) time. The first is unmaintainable; the second is friendly to any future reader.

  • Writing comments that just restate the code: i += 1 # add one to i — says nothing useful.
  • Letting comments become stale: the comment says one thing but the code does another, after a change.
  • Using single-letter variable names outside of short loops — future readers cannot tell what they mean.
  • Mixing tabs and spaces — Python raises TabError in inconsistent files.
  • Cramming many statements on one line (x=1;y=2;z=3) — legal but unreadable.

Curriculum expectation: Strand A, Expectation A3.2 — "apply accepted style conventions to programs (meaningful identifiers, consistent indentation, internal comments, descriptive function docstrings)".
