3.1 — Defining and Calling Functions
def, the function body, the return statement; pure functions vs. side effects; docstrings
# A function definition and three calls def area_rectangle(length, width): """Return the area of a rectangle.""" return length * width print(area_rectangle(5, 3)) # 15 print(area_rectangle(10, 2)) # 20 print(area_rectangle(7.5, 4)) # 30.0
📖 Lesson Notes — Ontario Curriculum

A function is a named piece of reusable code that performs a specific task. Functions are the most important tool for managing complexity: instead of repeating the same code in many places, you write it once and call it by name. Calling a function passes arguments (the values you supply) to its parameters (the names listed in the definition); the function runs its body, optionally produces a return value, and execution resumes where the call was made. The function definition uses the keyword def, followed by the function's name, parentheses listing parameters, and a colon. The body is indented underneath.

A return statement sends a value back to the caller and immediately ends the function. If a function does not execute a return statement, it implicitly returns None. This is fine for functions whose only purpose is a side effect (printing, modifying a list, writing a file). A function with no side effects whose return value depends only on its inputs is called pure — pure functions are easier to test and reason about. As a rule, prefer pure functions where you can; isolate side effects in a few well-marked functions.

The first line inside a function may be a docstring: a string literal (usually triple-quoted) that documents the function's purpose. Docstrings serve two roles: they explain the function to human readers, and they are accessible at runtime through the help() built-in. A good docstring states what the function does, its parameters, and its return value — nothing more, nothing less.

  • Function — a named, reusable block of code.
  • Definition — the def statement that creates the function.
  • Call (invocation) — the expression that runs the function, written name(arg1, arg2, ...).
  • Parameter — a name in the function definition that receives an argument.
  • Argument — the actual value passed in at a call site.
  • Return value — the value the function sends back to the caller.
  • Side effect — any change the function makes to the world outside itself (print, file write, mutate a list).
  • Docstring — a triple-quoted documentation string at the start of a function.

Worked example — a small helper function

def fahrenheit_to_celsius(f):
    """Convert a temperature from Fahrenheit to Celsius."""
    return (f - 32) * 5 / 9

# Two calls; the second uses the first
freezing = fahrenheit_to_celsius(32)   # 0.0
boiling  = fahrenheit_to_celsius(212)  # 100.0

print(f"Freezing: {freezing} C")
print(f"Boiling:  {boiling} C")

Writing the conversion once as a function lets us reuse it without copy-pasting the formula. The function is pure: same input, same output, no side effects. Each call runs in O(1). If we later discover the formula was wrong, we change one place. That is the essence of modular programming.

Worked example — pure vs. side-effect functions

# Pure: returns a value, no side effects
def double(x):
    return x * 2

# Side-effect: prints, returns None
def announce(x):
    print(f"The value is {x}")

result = double(5)         # 10, no output yet
announce(result)           # prints; returns None

Mixing the two roles is a common beginner mistake: writing print(...) inside a function that should return a value, then being unable to use the answer later. Decide up front whether the function returns or prints, and follow through.

  • Forgetting return — Python silently returns None, often producing puzzling downstream errors.
  • Confusing a function definition with a call: def f(): defines, f() calls. You must do both.
  • Using a function before defining it — in Python you must define a function in the file before any call that runs at module load time.
  • Using print inside a function and expecting the caller to use the printed value — print writes to the terminal, it does not return.
  • Re-using a parameter name as a local variable inside the function — usually fine, but can confuse readers.

Curriculum expectation: Strand A, Expectation A3.1 — "write functions that accept parameters and return values".

3.2 — Parameters, Arguments, and Default Values
Positional vs. keyword arguments; default parameter values; multiple return values via tuples
# Default parameter and keyword argument def greet(name, greeting="Hello"): return f"{greeting}, {name}!" print(greet("Ada")) # Hello, Ada! print(greet("Bob", "Welcome")) # Welcome, Bob! print(greet(name="Cay", greeting="Hi")) # Hi, Cay!
📖 Lesson Notes — Ontario Curriculum

Functions become more flexible once we allow more than one way to pass values in. Positional arguments match parameters by their order: area_rectangle(5, 3) sets length=5 and width=3 because of how they appear in the definition. Keyword arguments match by name: area_rectangle(width=3, length=5) works regardless of order and is more readable when there are several parameters. You can mix the two, but all positional arguments must come before any keyword argument.

Default parameter values let a parameter be omitted at the call site: def greet(name, greeting="Hello") allows greet("Ada") — the missing greeting receives its default value. Defaulted parameters must come after all non-defaulted ones in the definition. Defaults are evaluated once at function-definition time; using a mutable default like [] is a famous Python trap that we will see again in ICS4U.

A Python function may return multiple values by listing them after return, separated by commas. Technically, this packages them into a tuple; the caller can unpack the tuple into separate names: quotient, remainder = divmod(17, 5). This pattern is everywhere in idiomatic Python and is a powerful tool for clean code.

  • Positional argument — matched to a parameter by order.
  • Keyword argument — matched to a parameter by name.
  • Default value — a fallback used when an argument is omitted.
  • Tuple — an immutable ordered group of values, written with commas (optionally with parentheses).
  • Tuple unpacking — assigning each element of a tuple to a separate name.
  • Function signature — the function name and parameter list, defining the calling contract.

Worked example — a function that returns two values

def min_and_max(numbers):
    """Return (minimum, maximum) of a non-empty list."""
    smallest = numbers[0]
    largest  = numbers[0]
    for n in numbers[1:]:
        if n < smallest:
            smallest = n
        if n > largest:
            largest = n
    return smallest, largest

lo, hi = min_and_max([4, 1, 9, 2, 7])
print(lo, hi)   # 1 9

The function returns a tuple (smallest, largest) by simply listing them after return. The caller unpacks the tuple in a single assignment, getting two clean variable names. Total time is O(n) in the length of the list; memory is O(1) extra.

Worked example — default parameter for currency

def format_money(amount, currency="$"):
    return f"{currency}{amount:.2f}"

print(format_money(12.5))           # $12.50
print(format_money(12.5, "CAD "))   # CAD 12.50
print(format_money(12.5, currency="EUR ")) # EUR 12.50

The default makes the common case (Canadian dollars) easy while still permitting other currencies. Keyword form (currency="EUR ") is identical to positional form here but makes the call more self-documenting in code where the function takes many parameters.

  • Putting a non-defaulted parameter after a defaulted one: def f(x=1, y) — SyntaxError.
  • Passing keyword arguments before positional ones: f(x=1, 2) — SyntaxError.
  • Using a mutable default like def f(lst=[]) — the list is shared across calls; use lst=None and create a fresh list inside.
  • Forgetting that returning multiple values packages them into a tuple: x = min_and_max(...) gives a tuple, not the first value.
  • Calling a function with the wrong number of arguments — TypeError.

Curriculum expectation: Strand A, Expectation A3.1 — "write functions that accept parameters and return values; explain the difference between formal parameters and arguments".

3.3 — Variable Scope: Local and Global
Local variables; the global namespace; why mutable globals are dangerous; the global keyword (rarely used)
PI = 3.14159 # global constant — safe to read everywhere def circle_area(radius): area = PI * radius ** 2 # 'area' is LOCAL to this function return area print(circle_area(3)) # 28.27431 # print(area) — NameError: 'area' is not defined out here
📖 Lesson Notes — Ontario Curriculum

The scope of a variable is the region of code where the variable is visible. Variables created inside a function are local: they live only while the function is running and disappear when it returns. Variables created at the top level of a script are global: they are visible everywhere, including inside functions. Local and global variables are separate names, even if they happen to be spelled the same way; the function's local x has nothing to do with a global x that exists outside.

This sounds restrictive but is actually a powerful safety feature. Two functions can each use i as a loop variable without interfering with each other, because each function's i is its own local variable. Function parameters are local variables too — the parameter x in def f(x): ... is a fresh name that exists only inside f.

You can modify a global variable from inside a function using the global keyword, but it is almost always a bad idea. Code that uses many globals is hard to reason about because any function might change them. The professional convention is: pass values in as parameters and return results explicitly. Globals are appropriate only for constants (values that never change, conventionally named in UPPER_CASE) like PI or MAX_STUDENTS.

  • Scope — the region of code where a name is visible.
  • Local variable — defined inside a function; exists only during that call.
  • Global variable — defined at module/script top level.
  • Constant — a global value intended never to change (Python convention: UPPER_CASE).
  • Shadowing — a local name hiding a global one with the same identifier.
  • NameError — raised when a name is referenced but not defined in any visible scope.
  • Parameter — a local variable that receives an argument at call time.

Worked example — scope in action

def show():
    x = 5            # local
    print("inside:", x)

x = 100              # global
show()               # prints: inside: 5
print("outside:", x) # prints: outside: 100

The function's x and the global x are completely separate. Assigning to x inside show creates a brand-new local; it does not change the global. After show() returns, the local x is gone forever.

Worked example — globals done right and wrong

# GOOD: a named constant
SPEED_OF_LIGHT = 299792458   # metres per second

def travel_time(distance):
    return distance / SPEED_OF_LIGHT

# BAD: a mutable global modified across functions
running_total = 0

def add(x):
    global running_total
    running_total += x       # changes shared state

def reset():
    global running_total
    running_total = 0

The constant is fine: every reader knows it never changes. The mutable global, in contrast, ties the two functions together in an invisible way — calling add changes what later calls see. Passing the running total as a parameter, or wrapping it in an object, makes the dependency explicit.

  • Trying to modify a global without declaring global — Python creates a new local instead, and the global is unchanged.
  • Reading a name that doesn't exist anywhere — NameError.
  • Reusing the same name for a local in one function and a global — works but is confusing.
  • Using globals to "communicate" between functions — pass parameters and return values instead.
  • Forgetting that function parameters are local to that function only.

Curriculum expectation: Strand A, Expectation A3.1 — "explain the difference between formal parameters and arguments, and between local and global variables".

3.4 — Lists (1-D Arrays)
List literals; indexing (zero-based and negative); slicing; common methods (.append, .pop, .insert, .remove, len); iterating over a list
scores = [82, 76, 91, 68, 88] print(scores[0]) # 82 (first element) print(scores[-1]) # 88 (last element) print(scores[1:4]) # [76, 91, 68] print(len(scores)) # 5 scores.append(95) # now [82, 76, 91, 68, 88, 95] total = sum(scores) average = total / len(scores) print(f"Average: {average:.1f}")
📖 Lesson Notes — Ontario Curriculum

A list (called an array in many languages) is an ordered collection of values stored under a single name. Lists are the most useful data structure in computing because so many real-world things are naturally ordered collections: scores, names, sensor readings, words in a sentence. In Python you write a list literal with square brackets: [82, 76, 91]. Lists are indexed starting at 0: scores[0] is the first element, scores[1] the second, and so on. Negative indices count from the end: scores[-1] is the last element, scores[-2] the second-to-last.

Slicing extracts a range of elements: scores[1:4] returns a new list with elements at positions 1, 2, and 3 — the start is inclusive, the stop is exclusive, and the length of the slice is always stop - start. This half-open convention takes some getting used to but eliminates many off-by-one errors. scores[:3] takes the first three; scores[3:] takes everything from position 3 onwards; scores[:] makes a complete copy of the list.

Lists are mutable: you can change them after creation. The common modifier methods are .append(x) (add to the end), .insert(i, x) (insert at position i), .pop() (remove and return the last), .pop(i) (remove and return position i), and .remove(x) (remove the first occurrence of x). The built-in len(lst) returns the number of elements; sum(lst), min(lst), and max(lst) work on numeric lists. The in operator tests membership: 91 in scores is True.

  • List / array — an ordered collection of values stored under one name.
  • Index — a zero-based integer position into a list.
  • Slice — a sub-range of a list given by lst[start:stop].
  • Element — one value in a list.
  • Length (len) — the number of elements.
  • Mutable — can be changed after creation.
  • Membership (in) — tests whether a value appears in the list.
  • Aliasing — two names referring to the same list (changes through one are visible through the other).

Worked example — finding the average and the highest

def class_stats(marks):
    """Return (count, average, highest) for a list of marks."""
    if len(marks) == 0:
        return 0, 0.0, None
    count   = len(marks)
    average = sum(marks) / count
    highest = max(marks)
    return count, average, highest

n, avg, hi = class_stats([82, 76, 91, 68, 88])
print(f"{n} students; avg {avg:.1f}; high {hi}")
# 5 students; avg 81.0; high 91

The function uses three built-ins (len, sum, max), each O(n) in the list length, so the total is O(n). Guarding against the empty list prevents a division-by-zero error and returns sensible defaults. Returning a tuple of three values is idiomatic; the caller unpacks them in one line.

Worked example — building a list with a loop

# Read 5 marks from the user and store them.
marks = []                          # start empty
for i in range(5):
    m = float(input(f"Mark {i+1}: "))
    marks.append(m)                 # grow by one each iteration

print("Sorted:", sorted(marks))     # sorted() returns a new list
print("Average:", sum(marks)/len(marks))

The accumulator pattern adapted to a list: start with [], append inside the loop, use the result afterwards. sorted(marks) returns a sorted copy without changing the original. marks.sort() would sort in place and return None.

  • Index out of range: scores[5] when the list has only 5 elements — the last valid index is 4 (len(lst) - 1).
  • Calling .append expecting a new list back — it returns None and mutates the original.
  • Confusing sort() (in-place, returns None) with sorted(lst) (returns a new sorted list).
  • Aliasing: b = a does not copy; both names refer to the same list. Use b = a[:] or b = list(a).
  • Removing items by index while iterating — can skip elements.

Curriculum expectation: Strand A, Expectation A1.3 — "use one-dimensional arrays or lists to store and retrieve a collection of related values".

3.5 — Strings as Sequences
Strings are immutable sequences of characters; common string methods (.upper, .lower, .strip, .split, .replace, .find); iterating over characters
# Strings behave a lot like lists of characters name = "Ada Lovelace" print(len(name)) # 12 print(name[0]) # A print(name[-1]) # e print(name[4:]) # Lovelace print(name.upper()) # ADA LOVELACE print(name.replace(" ", "_")) # Ada_Lovelace print("Lovelace" in name) # True
📖 Lesson Notes — Ontario Curriculum

A string is an ordered sequence of characters — technically Unicode code points. Many of the operations that work on lists also work on strings: len(s), indexing (s[0]), negative indices (s[-1]), slicing (s[1:5]), iteration (for ch in s), and the in membership operator. The big difference between strings and lists is mutability: strings are immutable. You cannot write s[0] = "X"; every "modification" actually produces a new string. This is why s.upper() returns a new uppercase string rather than changing s in place.

Python strings have a rich set of methods that every Grade-11 student should know. .upper() and .lower() change case. .strip() removes whitespace from both ends; .lstrip() and .rstrip() remove from only one end. .replace(old, new) substitutes every occurrence. .split(sep) breaks a string into a list of pieces around the separator; sep.join(list) is its inverse. .find(sub) returns the index of the first occurrence or -1 if not found. .startswith(p) and .endswith(s) test prefixes and suffixes.

String concatenation with + joins two strings end to end: "Hello, " + name. Repetition with * repeats a string: "ab" * 3 is "ababab". For building up long strings inside a loop, collecting parts in a list and joining at the end is far faster than repeated +=: each += copies the whole accumulated string, costing quadratic time over the loop, while "".join(parts) is linear.

  • String — an immutable ordered sequence of characters.
  • Character — a single Unicode code point.
  • Substring — a contiguous slice of a string.
  • Method — a function attached to a string, called with dot notation.
  • Concatenation (+) — joining strings end to end.
  • Repetition (*) — repeating a string a number of times.
  • Tokenisation — splitting a string into pieces (words, fields) using .split.
  • Palindrome — a string that reads the same forwards and backwards.

Worked example — counting words in a sentence

def word_count(sentence):
    """Return the number of whitespace-separated words."""
    words = sentence.split()         # split on any whitespace
    return len(words)

print(word_count("The quick brown fox"))   # 4
print(word_count("   hello    world  "))   # 2  — extra spaces ignored

str.split() with no argument splits on any run of whitespace and discards empty pieces — perfect for word counting. With an argument like split(",") it splits on every comma, including empty fields.

Worked example — building a string from parts

def initials(full_name):
    """Return uppercase initials, e.g. 'Ada Lovelace' -> 'A.L.'"""
    parts = full_name.split()
    letters = []
    for word in parts:
        letters.append(word[0].upper())
    return ".".join(letters) + "."

print(initials("Ada Lovelace"))           # A.L.
print(initials("alan mathison turing"))   # A.M.T.

The algorithm splits the name into words, takes the first letter of each (uppercased), and joins them with periods. Total runtime is O(n) in the length of the full name. The pattern (split → transform → join) appears constantly in real text-processing code.

  • Trying to modify a string in place — s[0] = "X" raises TypeError.
  • Building a long string with repeated s = s + char — O(n2) work. Use a list and "".join.
  • Confusing .find (returns -1 on miss) with .index (raises ValueError).
  • Forgetting that string comparison is case-sensitive: "hi" == "Hi" is False.
  • Calling s.upper() and discarding the result, expecting s to change.
