5.1 — Hardware, Software, and How a Computer Works
CPU, RAM, storage, I/O; the fetch-execute cycle; binary and hexadecimal; bits and bytes
# Python sees binary natively with the 0b prefix. # Convert between decimal, binary, and hexadecimal. print(bin(42)) # 0b101010 print(hex(255)) # 0xff print(int("101010", 2)) # 42 — parse binary print(int("ff", 16)) # 255 — parse hex
📖 Lesson Notes — Ontario Curriculum

A computer is a machine that performs calculations and stores results. Its hardware — the physical parts — consists of four broad categories. The CPU (central processing unit) executes the instructions of the running program. RAM (random-access memory) is fast but volatile working storage — everything in RAM disappears when the power is cut. Storage — hard disks or solid-state drives — holds data persistently. Input/output devices — keyboard, mouse, screen, speakers, network card — let the computer interact with the outside world. Software is the set of instructions that runs on the hardware: an operating system, applications, and the programs you write yourself.

At the lowest level, every value — numbers, letters, images, sound — is stored as a binary sequence of bits (0 or 1). Eight bits group into a byte, which can represent 256 distinct values (28). Numbers use a place-value system just like decimal, but with base 2 instead of base 10: 1010 in binary means 1·8 + 0·4 + 1·2 + 0·1 = 10. Characters use an encoding such as ASCII (the letter 'A' is the byte 65) or Unicode UTF-8 (which covers every writing system in the world). Hexadecimal (base 16) is a compact way to write binary: each hex digit represents exactly four bits.

The CPU operates in a continuous fetch-decode-execute cycle: fetch the next instruction from memory, decode what it means, execute it, and repeat. Modern CPUs run billions of these cycles per second (a 3 GHz CPU does 3 billion cycles per second). They contain many tricks — pipelines, caches, branch prediction, multiple cores — but the basic loop is the same as Babbage's Analytical Engine sketched in 1837.

  • Hardware — the physical components of a computer.
  • Software — programs and data that direct the hardware.
  • CPU — central processing unit; the chip that executes instructions.
  • RAM — volatile working memory.
  • Storage — persistent storage (HDD, SSD).
  • Bit / byte — a binary digit / a group of 8 bits.
  • Binary — base 2 representation; only digits 0 and 1.
  • Hexadecimal — base 16 representation; digits 0–9 and A–F.
  • Fetch-decode-execute — the basic cycle of any CPU.

Worked example — converting numbers between bases

# Decimal 42 to binary, by repeated division by 2 (read remainders bottom-up):
# 42 / 2 = 21 r 0
# 21 / 2 = 10 r 1
# 10 / 2 = 5  r 0
#  5 / 2 = 2  r 1
#  2 / 2 = 1  r 0
#  1 / 2 = 0  r 1
# Reading remainders bottom-up: 101010

# Binary to decimal: 101010
# = 1*32 + 0*16 + 1*8 + 0*4 + 1*2 + 0*1 = 42

# Hex shortcut: group binary into 4-bit nibbles from the right
# 101010 -> 0010 1010 -> 2 A -> 0x2A
# In Python: hex(42) -> '0x2a'

Memorise a few small powers of 2: 1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024. With those the conversion between decimal and binary becomes near-instant.

  • Confusing the CPU with the computer — the CPU is one part inside the case.
  • Saying "memory" when you mean "storage" or vice versa — RAM is volatile working memory; disk is persistent storage.
  • Forgetting that 1 KB is technically 1024 bytes, not 1000 — (the unit "kibibyte" exists for the strict 1024 form, but everyday usage is loose).
  • Mixing bits and bytes — internet speeds are quoted in bits per second (b), but file sizes in bytes (B). 100 Mbps is 12.5 MB per second.
  • Assuming software runs "on RAM" — it runs on the CPU; RAM holds it temporarily.

Curriculum expectation: Strand C, Expectation C1.1 — "identify the major hardware components of a computer system (CPU, RAM, storage, input/output devices) and describe the role of each".

5.2 — Operating Systems and File Management
What an OS does (processes, files, memory, devices); file systems and paths; common operating systems
📖 Lesson Notes — Ontario Curriculum

An operating system (OS) is the program that manages all the other programs. Without an OS the hardware would do nothing useful — the OS provides the services that every application depends on. It manages processes (running programs), schedules them on the CPU so each gets its share, allocates and protects memory, organises long-term storage into a file system, provides a user interface (graphical or command-line), and talks to hardware devices through drivers. The major OSes today are Windows (Microsoft), macOS (Apple), Linux (free and open-source, with many distributions), Android (mobile, based on Linux), and iOS (mobile, by Apple).

The file system organises files into a tree of directories (also called folders). Every file has a path identifying where it lives: C:\Users\ada\notes.txt on Windows, /home/ada/notes.txt on Linux/macOS. An absolute path starts from the root; a relative path is interpreted from the current directory. Each file usually has an extension (the part after the last dot) such as .py, .txt, .png, or .pdf; the extension hints at the file's type but does not by itself determine its content.

The OS also enforces permissions: which users may read, write, or execute each file. This is the first line of defence against malware and accidental damage. On personal computers most students run as an administrative user, but on servers and shared systems unprivileged accounts cannot modify the system or other users' files. Understanding permissions — and the related distinction between user-mode and kernel-mode — will become important if you continue into systems programming or cybersecurity.

  • Operating system — the program that manages hardware and runs other programs.
  • Process — a running program with its own memory.
  • Scheduler — the part of the OS that decides which process runs next.
  • File system — the organisation of files and directories on storage.
  • Path — the address of a file in the file system (absolute or relative).
  • Directory / folder — a container that holds files and other directories.
  • Driver — OS code that talks to a specific hardware device.
  • Shell / command line — a text interface to the OS for running commands.

Worked example — reading paths and navigating

# A few common command-line operations:
#
# pwd               — print working directory (where am I?)
# ls                — list files in current directory
# cd notes          — change directory into "notes"
# cd ..             — move up one level
# mkdir week5       — make a new directory
# cp a.py b.py      — copy
# mv old.txt new.txt — rename / move
# rm scratch.txt    — delete (no undo!)
#
# Path examples:
#   ./marks.csv        relative, same dir
#   ../shared/data.csv relative, parent's "shared" subdir
#   /home/ada/marks.csv absolute (Linux/macOS)
#   C:\Users\ada\marks.csv absolute (Windows)

The command-line is faster than the GUI for routine tasks once you learn a dozen commands. Every professional developer is comfortable in some form of shell (Bash, Zsh, PowerShell). Practising on your own machine pays dividends quickly.

  • Assuming a file's extension determines its content — renaming .exe to .txt does not make it text; the bytes are unchanged.
  • Deleting files with rm at the terminal expecting them to land in the recycle bin — on most systems they are gone immediately.
  • Hard-coding absolute paths in a program (C:\Users\ada\...) — the program will not run for any other user. Use relative paths.
  • Forgetting that Windows uses \ and Linux/macOS use / in paths. Python's pathlib module hides the difference.
  • Running unknown executables without checking what they are — major source of malware infection.

Curriculum expectation: Strand C, Expectation C1.2 — "describe the function of an operating system (process management, file system, user interface, device drivers)".

5.3 — Networks and the Internet
Local networks; the Internet; IP addresses, DNS, URLs; clients and servers; HTTPS; cloud computing at a high level
📖 Lesson Notes — Ontario Curriculum

A network is two or more computers connected so they can exchange information. A small home network might have a few devices connected through a router; the Internet is the global network of networks, connecting billions of devices. Computers on a network identify each other by IP address — a numeric label such as 142.250.65.46 (IPv4) or a longer hexadecimal form (IPv6). Because numbers are hard to remember, the Domain Name System (DNS) translates human-readable names like mindview.pages.dev into IP addresses behind the scenes. When you type a name into a browser, the browser asks a DNS server for the address, then connects to that address.

Most Internet traffic follows the client-server pattern. A client (your browser, a phone app, a Python script) sends a request to a server (a machine specifically configured to wait for and answer requests). The server processes the request and sends back a response. The most common protocol for web pages is HTTP, and its encrypted version HTTPS; the "S" stands for "Secure" and means the communication is encrypted with TLS so eavesdroppers on the network cannot read it. Look for the padlock icon in the browser address bar — it indicates HTTPS is in use and that the server's identity has been verified.

The popular term cloud computing means renting computing resources (servers, storage, databases) from a provider such as AWS, Google Cloud, Microsoft Azure, or Cloudflare. Instead of buying your own hardware, you pay only for what you use. Web apps like Gmail, Google Docs, or this very course site run on cloud infrastructure. The benefits are scalability (handle traffic spikes) and lower up-front cost; the trade-offs include dependency on the provider, data-locality issues, and privacy questions about where your information is physically stored.

  • Network — computers connected to exchange data.
  • Internet — the global network of networks.
  • IP address — a numeric label uniquely identifying a device on a network.
  • DNS — the system that maps names to IP addresses.
  • URL — the address of a web resource (e.g., https://example.com/page).
  • Client / server — requesting program / responding program.
  • Protocol — a set of rules governing how two programs talk to each other (HTTP, HTTPS, FTP, SMTP).
  • HTTPS — HTTP over an encrypted TLS connection.
  • Cloud computing — renting computing resources from a remote provider.

Worked example — what happens when you load a web page

You type:  https://mindview.pages.dev/

1. Browser checks its cache for the IP of mindview.pages.dev.
2. If not cached, it asks a DNS server. DNS returns an IP.
3. Browser opens a TCP connection to that IP on port 443 (HTTPS).
4. Browser and server perform a TLS handshake to establish encryption.
5. Browser sends an HTTPS GET request:  GET / HTTP/1.1
6. Server responds with HTML, CSS, JavaScript, images.
7. Browser parses the HTML and renders the page on screen.
8. The page may request more resources, repeating steps 4-7.

Every step happens automatically and usually completes in under a second. Hundreds of layers of engineering go into making this seem effortless. If anything fails — DNS, TLS, the server — the browser shows an error page; understanding which step failed is the first skill of network troubleshooting.

  • Confusing the Internet with the Web. The Web (HTTP/HTTPS pages and links) is one service that uses the Internet; email, video calls, and online gaming are others.
  • Believing "the cloud" is a single place — it is hundreds of data centres around the world.
  • Trusting the padlock icon as proof of safety — it confirms encryption to the named server, not that the server itself is trustworthy.
  • Assuming local IP addresses (like 192.168.x.x) are visible on the Internet — they are private to your network, hidden behind your router's public address.
  • Confusing bandwidth (megabits per second) with latency (round-trip delay) — the two have different effects on user experience.

Curriculum expectation: Strand C, Expectation C2.2 — "describe how a computer connects to a network and to the Internet (NIC, router, IP address, DNS) at a non-technical level".

5.4 — Cybersecurity and Privacy
Common attacks (phishing, malware, weak passwords, social engineering); defences (MFA, updates, password managers); privacy online; digital footprint
📖 Lesson Notes — Ontario Curriculum

Cybersecurity is the practice of protecting computers, networks, and data from unauthorised access, attack, or damage. The threats are real and growing: the average Ontario student will be the target of phishing attempts, password leaks, and other attacks many times per year. Understanding both the attacks and the defences is now essential digital literacy. The most common attacks are phishing (tricking the user into giving away credentials, usually via a fake email or web page), malware (malicious software installed on the user's device), password attacks (guessing or stealing passwords), and social engineering (manipulating people rather than software).

A small number of habits provide most of the protection. (1) Use strong, unique passwords for every site, ideally generated and stored by a password manager. A 16-character random password is essentially uncrackable; "Password123" is broken in seconds. (2) Turn on multi-factor authentication (MFA) wherever offered — even if your password leaks, the attacker still cannot log in without the second factor (phone code, security key, biometric). (3) Keep your operating system and applications up to date; security patches close holes that attackers actively use. (4) Be sceptical of unexpected messages asking you to click a link or open an attachment, especially if they create urgency ("Your account will be closed in 24 hours!"). (5) Back up important data so a ransomware attack or hardware failure does not erase your work.

Privacy is related but distinct: the protection of personal information from misuse. Every site you visit, every app on your phone, every smart device in your home potentially collects data about you — your location, your contacts, your interests, your activity over time. This digital footprint is permanent and largely outside your control once shared. Practical privacy steps include reviewing app permissions, using a browser that blocks trackers, being thoughtful about what you post on social media, and reading privacy policies before signing up. Canada's Personal Information Protection and Electronic Documents Act (PIPEDA) and Ontario's privacy legislation give individuals some rights to access and correct their data held by organisations.

  • Cybersecurity — protecting systems and data from attack.
  • Phishing — a fake message designed to trick the recipient into revealing credentials.
  • Malware — malicious software (viruses, worms, ransomware, spyware).
  • Password manager — a program that generates and stores strong, unique passwords for each site.
  • Multi-factor authentication (MFA) — requiring more than one proof of identity to log in.
  • Encryption — converting data into a form unreadable without the key.
  • Digital footprint — the trail of data you leave online.
  • Privacy policy — a statement of how an organisation handles personal information.

Worked example — recognising a phishing email

Subject: URGENT — Your school account will be suspended!
From: support@scholl-board.com    ← misspelled domain
"Click here within 24 hours to verify your password or
 your account will be permanently deleted..."
Link points to: http://verify-school.ru/login.html    ← strange host

Red flags:
 1. Misspelled sender domain.
 2. Artificial urgency ("24 hours").
 3. Asks for password directly.
 4. Link uses HTTP (not HTTPS) and a strange domain.
 5. Generic greeting ("Dear student").

Correct response:
 1. Do NOT click the link.
 2. Do NOT reply.
 3. Report it to your school's IT helpdesk.
 4. Delete the message.

Phishing has improved over the years — modern attempts can be very convincing — but the warning signs above appear in most cases. When in doubt, contact the alleged sender through a known channel (the school website, the bank's phone number on your card), not the contact information in the suspicious message.

  • Reusing the same password across multiple sites — a leak at one site compromises all of them.
  • Trusting an email solely because it appears to come from a familiar sender — "From" lines can be forged.
  • Believing a site is safe just because the URL contains the brand name — microsoft-login.fake.ru is not Microsoft.
  • Sharing too much on social media — vacation photos with location data tell burglars you are not home.
  • Ignoring software updates because they are inconvenient — the gap between a security patch and an exploit can be hours.

Curriculum expectation: Strand D, Expectation D1.2 — "describe what is meant by cybersecurity, and identify common attack types and basic defences".

5.5 — Ethics, AI, and Environmental Impact
Programmers' ethical responsibilities; AI and machine learning at a high level; software licensing; environmental footprint of computing
📖 Lesson Notes — Ontario Curriculum

Software shapes daily life: it decides what you see in your social feed, how your bank approves loans, which job applicants get interviews. With this influence comes responsibility. Professional programmers operate under ethical codes (such as the ACM Code of Ethics) that require them to consider the impact of their work on users, on third parties, and on society. The core principles are familiar: be honest, do not harm, respect privacy, give credit, accept criticism, and continue learning. Although Grade 11 students are not yet professionals, beginning to think about these questions is the right first step.

Artificial intelligence (AI) is software that performs tasks usually associated with human intelligence: recognising images, translating languages, holding conversations, playing games. Modern AI is dominated by machine learning, in which a computer learns patterns from large amounts of training data rather than being told the rules explicitly. Large language models (LLMs) like ChatGPT or Claude are trained on enormous text corpora and can produce fluent, useful text — but they also produce confident-sounding nonsense (hallucinations), reproduce biases present in training data, and can be used to mislead or deceive at scale. Treat AI output as a draft, not a source of truth, and always verify important facts.

Software licensing determines what you may legally do with code others have written. Proprietary software (Microsoft Office, Photoshop) is owned by a company and used under restrictions. Open-source software (Python, Linux, Firefox) is released under a licence that lets you read, modify, and redistribute the code — with some conditions, such as keeping the original copyright notice or releasing your changes under the same licence. As a student, you should respect licences (do not pirate proprietary software; do not pass off open-source code as your own original work). Finally, the environmental footprint of computing is large: data centres consume a couple of percent of global electricity, the manufacture of devices produces e-waste and mining demand, and training large AI models takes huge amounts of energy. Choices like keeping devices longer, recycling electronics through proper channels, and questioning whether a problem really needs an AI solution are small ways to limit the impact.

  • Ethics — principles distinguishing right from wrong conduct.
  • AI / Artificial Intelligence — software performing tasks normally associated with human intelligence.
  • Machine learning — learning patterns from data instead of following hand-written rules.
  • Training data — the examples a model is trained on.
  • Hallucination — confidently-incorrect output from an AI model.
  • Algorithmic bias — systematic unfairness in software due to biased data or design.
  • Proprietary software — code owned and licensed under restrictions.
  • Open-source software — code released under a licence that allows inspection and modification.
  • E-waste — discarded electronic equipment.

Worked example — algorithmic bias in a real system

Case: A US tool used in courts to predict recidivism (re-offending)
was found in 2016 to flag Black defendants as "high risk" at almost
twice the rate of white defendants for the same actual outcomes.

Why does this happen?
 - Training data reflected historic, biased arrest patterns.
 - The model learned the bias without being explicitly told to.
 - The score then influenced bail and sentencing — amplifying the bias.

Mitigations:
 - Audit training data for representation and accuracy.
 - Test outputs across demographic groups, not just overall accuracy.
 - Be transparent about the model's limits.
 - Keep a human in the loop on consequential decisions.

This is the canonical example used in ethics discussions and is well documented in the ProPublica investigation. It shows that "the algorithm decided" is never a sufficient defence — humans built the algorithm and bear responsibility for it.

  • Treating AI output as authoritative without verification — LLMs invent confident answers.
  • Copying code without checking its licence — even open-source code has terms (attribution, copyleft).
  • Believing "the algorithm is neutral" — an algorithm is neutral only relative to the assumptions and data of its designers.
  • Ignoring environmental impact ("it's just electricity") — small choices, multiplied by billions of users, become large effects.
  • Conflating ethics with legality — many legal actions are unethical, and a few illegal actions (civil disobedience, whistle-blowing) may be ethical.

Curriculum expectation: Strand D, Expectation D2.2 — "distinguish open-source, free, and proprietary software licensing models, and the ethical responsibilities of programmers".

5.6 — Careers, Postsecondary Pathways, and History of Computing
CS pathways at Ontario universities and colleges; common career roles; landmark contributors including Canadians
📖 Lesson Notes — Ontario Curriculum

Computer science is one of the most flexible career launchpads. Graduates work in software development (web, mobile, desktop, embedded, game), data science & machine learning, cybersecurity, cloud and devops, UX/UI design, IT support and administration, computing research, and computing education. The skills also transfer to adjacent fields: business analytics, journalism (data journalism), engineering, the arts (digital media), and the sciences (bioinformatics, computational physics, climate modelling). Salaries are typically above the median for any given level of education, and the work-from-home culture of the industry makes geographic flexibility unusually high.

In Ontario, two main paths after high school lead into computing. The university path (BSc Computer Science, BSc Software Engineering, BEng Computer Engineering) typically lasts four years and emphasises theory, mathematics, and a co-op work program at many schools. Strong programs include the University of Waterloo (renowned co-op), University of Toronto, McMaster, Western, Queen's, Carleton, York, Ottawa, and Guelph. The college path (diploma or advanced diploma) typically lasts two or three years, is more hands-on and industry-aligned, and includes programs such as Computer Programmer / Programmer-Analyst, Game Development, Cybersecurity, Mobile Development, and Web Development. Strong programs include Seneca, Centennial, Sheridan, Algonquin, Conestoga, George Brown, and Humber. Both paths have produced excellent practitioners; choose based on your learning style and goals.

Computing has a rich history. Charles Babbage and Ada Lovelace (1830s-40s) designed the Analytical Engine and wrote the first algorithm intended for a machine. Alan Turing (1930s-50s) defined the theoretical model of computation that bears his name and broke German wartime codes. Grace Hopper built the first compiler and championed COBOL. John von Neumann formalised the stored-program architecture used in nearly every computer today. Canadian contributors include Stephen Cook (University of Toronto, who introduced the concept of NP-completeness in 1971), Geoffrey Hinton (University of Toronto, pioneer of deep learning and Nobel laureate in physics, 2024), Yoshua Bengio (Université de Montréal, another deep-learning pioneer), and Yann LeCun (Canadian-trained, currently at NYU and Meta). Understanding the lineage is more than trivia: it gives you a sense of how the field grew and where it might go.

  • Software developer — builds software products.
  • Data scientist — extracts insights from data using statistics and machine learning.
  • Cybersecurity analyst — defends systems and investigates incidents.
  • UX/UI designer — designs how users interact with software.
  • Devops / SRE — keeps production systems running reliably.
  • Co-op — alternating school terms with paid work placements (common at U of Waterloo and others).
  • NP-complete — a class of problems that no known efficient algorithm solves; Cook's 1971 contribution.
  • Deep learning — neural networks with many layers; Hinton/Bengio/LeCun were jointly awarded the 2018 Turing Award.

Worked example — planning a postsecondary path

Goal: Become a software developer at a tech company.

University route (4 years + co-op):
 - Prerequisites: ICS3U, ICS4U, MHF4U, MCV4U or MDM4U, ENG4U.
 - Sample programs: UWaterloo CS (co-op), UofT CompSci, McMaster CS,
   Western SE, Queen's CompSci, Carleton CompSci.
 - Strengths: strong theory, math, networking, often direct path to
   internships and full-time at top companies.

College route (2-3 years):
 - Prerequisites: high-school diploma; specific programs may vary.
 - Sample programs: Seneca Software Development, Sheridan Mobile Computing,
   Algonquin Game Development, Conestoga Cybersecurity.
 - Strengths: more hands-on, faster entry to the workforce, often easier
   admission. Bridging programs let graduates continue to a university
   degree if desired.

Sample Day 1 to Day 1 timeline:
 - Year 12 (this year): build a portfolio (GitHub) of small projects.
 - Apply OUAC or OCAS in November.
 - Decision letters in spring; reply by Ontario deadline.
 - Co-op students may get a placement as early as semester 2.

Either path leads to a viable career. The "best" school is the one where you will work hard and finish; what you build outside class (a portfolio of projects on GitHub, contributions to open source, hackathon entries) matters as much to employers as the institution name.

  • Believing only graduates of the most famous schools succeed — college graduates and self-taught developers are common in the industry.
  • Assuming you must specialise immediately — CS is broad; most graduates explore several roles before settling.
  • Skipping the math prerequisites for university — admissions averages and degree requirements both depend on them.
  • Treating a degree as the whole story — the portfolio, internship experience, and the ability to learn count for at least as much.
  • Overlooking interdisciplinary paths — computing + biology = bioinformatics; computing + economics = quantitative finance; computing + art = digital media.

Curriculum expectation: Strand D, Expectations D3.1 and D4.1 — "identify at least three university programs and three college programs in Ontario related to computer science" and "identify at least three landmark contributions to computing".
